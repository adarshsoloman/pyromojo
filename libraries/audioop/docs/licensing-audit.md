# Licensing and provenance audit: `audioop`

Status: Phase 0 analysis. This document records facts and the project's
planned handling; it does **not** offer legal advice or a legal conclusion.

## 1. The reference's licensing chain

`Modules/audioop.c` in CPython 3.12.3 is distributed as part of CPython under
the PSF-2.0 license. The file header additionally carries a provenance notice:

- the module "uses the code base in g777.c file of the Sox project", from
  `sox-12.17.7.tar.gz`;
- immediately below it, "Copyright of g771.c:" (upstream spells the file
  number inconsistently);
- a Sun Microsystems, Inc. unrestricted-use notice:

  > This source code is a product of Sun Microsystems, Inc. and is provided
  > for unrestricted use. Users may copy or modify this source code without
  > charge. […] SUN SOURCE CODE IS PROVIDED AS IS WITH NO WARRANTIES OF ANY
  > KIND […]. SUN MICROSYSTEMS, INC. SHALL HAVE NO LIABILITY WITH RESPECT TO
  > THE INFRINGEMENT OF COPYRIGHTS, TRADE SECRETS OR ANY PATENTS BY THIS
  > SOFTWARE OR ANY PART THEREOF. […]

The derived portion covers the u-law/A-law conversion routines (the `st_*`
functions and their tables) and the segment tables. The rest of the file
(ADPCM, resampling, statistics, fragment transforms) is CPython/PSF code.

SoX's own distribution license was **not** relied on for this analysis,
because the specific derived code carries its own embedded Sun notice. If any
SoX file were ever vendored or copied directly, that would require a separate
license review under the project's copyleft policy.

## 2. Project policy that applies

From `THIRD_PARTY_NOTICES.md`:

- upstream source is **not copied** into this repository by default;
- reference implementations are pinned external dependencies used for
  observation;
- test vectors derived from observed behaviour are stored in
  `tests/vectors/` and documented as derived data;
- copyleft material requires review before distribution, linking, or
  incorporation;
- attribution notices are retained for included material.

The repository is Apache-2.0; the library's own Mojo code will be Apache-2.0.

## 3. What the port will do

1. **Independent implementation.** The Mojo code is written from observed
   behaviour and the algorithm analysis, not by translating the C file. No C
   source, comments, or identifier names are copied.
2. **Tables regenerated, not transcribed.** The G.711 u-law/A-law decode
   tables are fully determined by the published companding formulas and are
   generated in Mojo from those formulas, then validated against observed
   outputs. The ADPCM step-size and index tables are standard IMA/DVI values;
   they will be produced from the published table in the specification and
   cross-checked against the reference's behaviour. If a table cannot be
   reproduced independently, the decision and the applicable notice will be
   revisited before release.
3. **Vectors are derived data.** `tests/vectors/audioop_vectors.json` is a
   record of outputs produced by running the pinned reference; it is not
   source code and contains no C.
4. **No new dependency.** Phase 0 adds neither a package pin nor a vendored
   file. The reference interpreter is local tooling
   (`python_reference/.venv`, git-ignored).

## 4. Attribution to retain

Before the first release, the library README (or its linked notice) must
record, at minimum:

- reference: CPython 3.12.3 `audioop` (stdlib, PSF-2.0);
- the Sun Microsystems unrestricted-use notice for the u-law/A-law routines
  derived from SoX `g777.c`/`g771.c` (quoted in full, as upstream does);
- a statement that the Mojo implementation is independent and that numerical
  vectors are derived from observed behaviour.

The exact paragraph is prepared here so it can be inserted into
`THIRD_PARTY_NOTICES.md` and the library README when implementation begins.
Phase 0 deliberately does not edit the shared notice file.

## 5. Why this is low risk (facts only)

- The derived notice grants unrestricted use, including copying and
  modification, without a fee.
- The port does not redistribute CPython or SoX binaries or sources.
- The port's own code is original; vectors are observed numerical outputs.
- The algorithms (G.711 companding, IMA ADPCM, linear resampling) are
  published standards with public specifications.

## 6. Residual questions for the release review

1. Whether generated G.711 tables should be accompanied by the Sun notice
   even though they are regenerated from the standard. Current position: keep
   the notice, because the reference's implementation derives from that code.
2. Whether the ADPCM tables are better generated by formula or emitted as
   standard constants; either way, the standard's published table is the
   source of truth.
3. Whether the library README or `THIRD_PARTY_NOTICES.md` is the canonical
   location for the notice (repo policy allows either; precedent in the other
   ports is the library README plus the shared file).
