# G.711 A-law and mu-law codecs (Phase 7)

Port of CPython 3.12.3 `audioop`'s four codec functions
(`mojo_audioop/g711.mojo`). The reference code derives from SoX 12.17.7
`g777.c`/`g771.c` (Sun Microsystems public-domain source).

## Implemented functions

| Function | Reference signature | Widths | Behaviour |
| --- | --- | --- | --- |
| `lin2alaw` | `lin2alaw(fragment, width)` | 1–4 | One A-law byte per sample. |
| `alaw2lin` | `alaw2lin(fragment, width)` | 1–4 | `width` bytes per input byte; **no alignment requirement**. |
| `lin2ulaw` | `lin2ulaw(fragment, width)` | 1–4 | One mu-law byte per sample. |
| `ulaw2lin` | `ulaw2lin(fragment, width)` | 1–4 | `width` bytes per input byte; **no alignment requirement**. |

## Encoding

Both encoders validate width and fragment alignment
(`audioop_check_parameters`), then scale every sample to the 32-bit
position (`GETSAMPLE32`, value × `2^(32−8·width)`) and shift **right**
(arithmetic) to the codec's input range:

| Width | lin2ulaw shift (total) | lin2alaw shift (total) |
| ---: | ---: | ---: |
| 1 | `<< 6` (×64) | `<< 5` (×32) |
| 2 | `>> 2` | `>> 3` |
| 3 | `>> 10` | `>> 11` |
| 4 | `>> 18` | `>> 19` |

So every width is normalized into the 14-bit (mu-law) or 13-bit
(A-law) magnitude range — 8-bit samples are scaled **up**, not down.

### mu-law (`st_14linear2ulaw`)

1. `mask = 0x7F` for negative samples (magnitude negated), `0xFF` for
   non-negative.
2. Clip the magnitude at `CLIP = 32635`.
3. Add the bias `BIAS >> 2 = 33`.
4. `seg = search(value, seg_uend, 8)` — first index with
   `value <= seg_uend[i]`, where
   `seg_uend = {0x3F, 0x7F, 0xFF, 0x1FF, 0x3FF, 0x7FF, 0xFFF, 0x1FFF}`.
5. `seg >= 8` (unreachable after clipping) returns `0x7F ^ mask`.
6. Otherwise `uval = (seg << 4) | ((value >> (seg + 1)) & 0xF)` and the
   output is `uval ^ mask` (mu-law inverts all bits).

### A-law (`st_linear2alaw`)

1. Non-negative: `mask = 0xD5`. Negative: `mask = 0x55` and
   `value = -value - 1` (A-law's even-bit-inversion convention).
2. `seg = search(value, seg_aend, 8)` with
   `seg_aend = {0x1F, 0x3F, 0x7F, 0xFF, 0x1FF, 0x3FF, 0x7FF, 0xFFF}`.
3. `seg >= 8` returns `0x7F ^ mask`.
4. Otherwise `aval = seg << 4`, then quantization bits:
   `(value >> 1) & 0xF` for segments 0–1, `(value >> seg) & 0xF` for
   segments 2–7; output `aval ^ mask`.

All arithmetic is integer; there is no rounding beyond the arithmetic
shifts. Clipping happens on the magnitude before the bias.

## Decoding

`ulaw2lin`/`alaw2lin` validate the **width only**
(`audioop_check_size`) — unlike the encoders, fragment alignment is not
required and any byte count is accepted. Every input byte indexes the
reference's 256-entry `int16` table (`_st_ulaw2linear16` /
`_st_alaw2linear16`), the value is multiplied by `2^16`, and the sample
is stored through `SETSAMPLE32` (top-aligned truncating shift):

| Width | Store shift | Effect |
| ---: | ---: | --- |
| 1 | `>> 24` | `decoded16 >> 8` (arithmetic; e.g. -32124 → -126) |
| 2 | `>> 16` | `decoded16` unchanged |
| 3 | `>> 8` | `decoded16 << 8` |
| 4 | none | `decoded16 << 16` |

The port embeds both 256-entry tables verbatim from the reference
source (`comptime StaticTuple[Int16, 256]`); the exhaustive
256-codeword differential tests (both codecs) prove exactness.

## Relationship to standard G.711

- The A-law mask/inversion (`0x55`/`0xD5`), segment tables, mu-law bias
  33 and bit-complement output follow the standard CCITT G.711
  quantization curves (they originate in Sun's public-domain `g711.c`).
- CPython-specific details: the exact `CLIP = 32635` point (standard
  mu-law clipping), the `val >> 18`/`val >> 19` input scaling of the
  32-bit samples, the width-1 **upscale** (×64 / ×32), the decoder's
  missing alignment check, and the fixed 16-bit decode tables.
- `lin2alaw`/`lin2ulaw` at width 1 are *not* simple truncations of
  wider samples; they scale the 8-bit range up to the codec range
  first. This is CPython behaviour, verified at all four widths.
- No undefined behaviour is reachable; no port policy deviations were
  needed.

## Validation and errors (verbatim)

- Encoders: `Size should be 1, 2, 3 or 4`, then
  `not a whole number of frames`.
- Decoders: `Size should be 1, 2, 3 or 4` only (alignment never
  checked); empty input is valid for both encoder and decoder.
